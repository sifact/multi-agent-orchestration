About this project

Ask a question in plain English and get an answer from the right company data.

This is a working AI assistant for Contoso Aero Engines, a fictional jet-engine maker. Its information is spread across five areas, from factory records to airline fleet data. Instead of someone working out which system to search and how to query it, people just ask, and the assistant finds the answer and shows how it got there.

You're looking at version 1 of 3. Each version changes how the AI specialists work together, and each one is scored on the same test questions, so you can see what every step gains and what it costs.

Try it in the playground See the three versions

The problem it solves

In most engineering companies, answers are scattered across separate systems: one for live sensor data, one for repairs, one for manufacturing, one for quality checks, and a pile of manuals. A simple question such as "Why was this engine removed?" can mean knowing the right system, the right table and the right query. That is slow, and only a few experts can do it.

How version 1 works

Each question passes through three steps. You can watch every step in the playground.

1

You ask

Type a question in everyday language. No query language or system names needed.

2

A router picks the expert

A quick AI step reads the question and sends it to the one specialist that owns that data, or politely refuses if it is off-topic or unsafe.

3

The specialist answers

The specialist looks up the facts, writes the answer, and shows the exact lookups it ran, so anyone can check the work.

The five specialists

Each specialist is an AI agent that can see only its own area, which keeps answers focused and data access tight. All three versions use the same five.

Telemetry

The airline fleet: which engines fly where, and their sensor readings and health trends.

"How many active engines does Northwind Air operate?"

Service

What happened in service: removals, shop visits, repairs and inspection findings.

"Why was engine CX7-10025 removed?"

Production

How each engine was built: the plant, the parts fitted and who supplied them.

"Which plant built engine CX7-10001?"

Quality

Factory inspections, defects found, and parts put on hold.

"Which lots are quarantined, and why?"

Knowledge

What the manuals and service bulletins say: procedures, limits and definitions.

"What does service bulletin SB-CX7-72-0042 require?"

The roadmap: three versions, one change at a time

The five specialists and the data stay the same in every version. What changes is how the specialists work together and how the software is built, and only one thing changes per step: v2 adds teamwork, then v3 splits the specialists into separate services. That way each change is measured on its own, and you can see exactly what it adds and what it costs.

Which version fits your company?

v1Most questions are about one area, and speed and cost matter most.
v2Questions often cross areas, and one team runs the whole system.
v3Several teams own different data, or parts of the system must scale and ship on their own.

How we measure it

"It seems to work" isn't good enough, so every version is scored against the same 59 test questions with known correct answers: 24 that one specialist can answer, 23 that need several, and 12 that it should refuse. The scoring runs on Microsoft's Azure AI Evaluation toolkit, so accuracy, speed and cost can be compared side by side across versions.

Built to be safe

These rules hold in every version.

  • Read-only. The assistant can look data up, but it can never change or delete anything.
  • Least access. Each specialist is blocked from every table outside its own area, and this is enforced by the database itself, not just by instructions to the AI.
  • Refuses what it should. Off-topic questions, requests to bypass a safety limit, and attempts to trick the AI into ignoring its rules are turned away before any data is touched.
  • Transparent. Every answer comes with the lookups behind it, plus the time and cost of the question.

The data and the technology

  • Real engine data. The sensor readings are real turbofan data published by NASA (C-MAPSS). The factory, fleet and repair records are realistic synthetic data linked to them. No real company's data is used.
  • Based on published patterns. Version 1 recreates the starting point that Microsoft's engineering team (ISE) describes in its article on orchestration patterns for multi-agent systems, and version 3 follows where they ended up. Version 2 sits in between, so the teamwork can be measured separately from the move to services.
  • Model-agnostic. It works with any OpenAI-compatible AI model, so it can run on Azure OpenAI or another provider. It currently uses an open-weight model.
  • Simple to run. It's plain Python with a small built-in database, and this playground runs entirely on your own machine.
